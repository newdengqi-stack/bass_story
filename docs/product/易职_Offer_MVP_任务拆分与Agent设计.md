# 易职 Offer MVP 任务拆分与 Agent 设计

## 1. 产品目标与当前边界

本轮 MVP 只服务于已经进入实习/校招准备期的嵌入式求职者。

用户目标是提升目标岗位的面试准备质量，并提高获得面试和 Offer 的可能性。产品对可控结果负责：验证项目证据、识别岗位差距、形成可信简历、支持持续复盘；不承诺 Offer、内推、代投或绕过学历和市场竞争。

当前不做职业探索、技术路线选择、完整学习路径、课程平台或泛化学习答疑。这些内容作为后续阶段，不占用 Offer MVP 的资源。

## 2. 用户流程

```text
选择目标岗位并提交 JD
          ↓
导入简历和已有项目
          ↓
提交项目证据（GitHub / 项目材料 / 多轮追问）
          ↓
验证项目深度，映射目标岗位要求
          ↓
生成岗位差距与冲刺任务
          ↓
形成基于证据的岗位专版简历
          ↓
模拟面试 / 真实面试复盘（后续）
          ↓
更新项目证据、差距优先级与下一步任务
```

MVP 最小闭环：

```text
目标岗位 → 项目验证 → 差距 → 简历
```

## 7. Agent 设计

### 7.1 总体原则

MVP 采用 **1 个流程协调器 + 4 个职责 Agent**。

这不是五个相互自主聊天的复杂智能体。首版可使用同一模型，通过不同的提示词、输入输出结构和业务规则实现。流程协调器负责调用顺序、数据传递、版本保存和权限边界，不自行做业务判断。

```text
用户提交 JD、简历、项目
        ↓
岗位分析 Agent
        ↓
项目证据验证 Agent
        ↓
差距与冲刺计划 Agent
        ↓
可信简历 Agent
        ↓
用户获得报告、任务和岗位专版简历
```

### 7.2 Agent 职责

| Agent | 用户价值 | 输入 | 输出 | MVP |
| --- | --- | --- | --- | --- |
| 岗位分析 Agent | 明确企业要求 | JD、岗位名称 | 标签、硬条件、岗位重点 | 是 |
| 项目证据验证 Agent | 判断项目能否经得起追问 | 项目材料、GitHub、用户回答、岗位标签 | 追问、证据状态、证据卡 | 是 |
| 差距与冲刺计划 Agent | 明确有限时间内先补什么 | 岗位标签、证据卡、求职时间 | 差距报告、优先级、任务 | 是 |
| 可信简历 Agent | 生成不虚构的岗位简历 | 原简历、JD、已验证证据 | 修改建议、岗位专版简历 | 是 |

### 7.3 Agent 协作规则

1. 岗位分析 Agent 只能解析 JD，不能评价用户能力。
2. 项目证据验证 Agent 是唯一可将能力标记为“已验证”的 Agent。
3. 差距与冲刺计划 Agent 只能读取证据状态，不得自行认定用户掌握某项技术。
4. 可信简历 Agent 只能使用已验证或用户确认的事实；不得补写技术栈、项目成果、量化指标或职责。
5. 所有 Agent 输出必须结构化保存，并保留输入来源、结论版本和证据状态。
6. 当 Agent 无法判断时，必须输出“证据不足”或追问，不得用猜测填补结论。

### 7.4 不单独创建泛答疑 Agent

当前 Offer MVP 不创建独立的学习答疑 Agent。项目深挖中用户遇到不会的问题时，由项目证据验证 Agent：

```text
识别不会的问题
→ 解释当前问题与岗位的关系
→ 给出小型补强任务
→ 用户完成后再次验证
```

这样答疑始终服务于 Offer 准备闭环，不会扩张成泛化学习平台。

## 8. MVP 范围

### MVP 必须完成

1. 创建一个主目标岗位并粘贴 JD。
2. 导入简历文本，建立至少一个项目档案。
3. 提交项目材料/GitHub 链接，或进入多轮项目追问。
4. 获得带来源的项目证据报告。
5. 获得岗位差距报告与下一步任务。
6. 获得基于证据的简历修改建议并保存文本版本。

### MVP 不包含

- 多岗位管理。
- PDF/DOCX 导出。
- 语音模拟面试、真人导师、完整算法判题。
- 真实面试复盘和外部资源库。
- 私有仓库授权、GitHub 深度代码分析。
- 职业探索、技术路线推荐、完整学习内容。

## 9. 第一阶段执行任务

第一阶段目标是先验证最薄但完整的业务闭环：

```text
一个 JD + 一个项目 → 追问验证 → 证据报告 → 差距任务
```

执行顺序：

1. T1、T2：定义目标岗位和能力标签。
2. T9、T13、T14、T16：建立项目档案和材料提交。
3. T17、T18：定义项目追问模板和证据状态规则。
4. T19、T20、T21、T22：完成最小项目追问会话。
5. T23、T24、T25：生成证据判定和项目报告。
6. T26、T27、T28、T29：生成岗位差距和下一步任务。

第一阶段通过后，再实施 E5 简历模块。原因是：只有项目验证确实能指出用户盲区，简历建议才具备可信基础。
