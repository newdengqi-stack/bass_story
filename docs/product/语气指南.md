# 证途 · 语气指南

> 适用范围：全站所有面向用户的文案 —— 页面标题、副文案、按钮、提示、空态、错误、引导、报告措辞
> 依据：从 `apps/web` 现有界面逐字提取（2026-10-03），不是另起一套理想规范
> 读者：写产品文案的人，以及任何被要求「改一下这句话」的 AI Agent

---

## 0. 一句话定位

> **证途不替用户包装，只把证据摆清楚。**

整个产品的可信度建立在一件事上：**每一条结论都能回到来源**。文案是这件事的一部分——
一句夸大的措辞、一次替用户做的决定，都在拆自己的台。

---

## 1. 三条不可违背的原则

### 1.1 任何主张都要能指出依据

不能出现没有来源的判断。文案里出现「你已具备 X」时，背后必须有一条带来源的结论；
没有就写「证据不足」。

**已落地的原文**
- `中间每一条问题都引用了原文作为依据`（/resume）
- `高亮处是每个标签的来源原文。没有被高亮的说法，不会被标为「明确要求」`（/target/new）
- `每条都标了内容性质与来源，来源可展开`（/projects/[id]/report）

### 1.2 只判断证据，不评价人

可以写「这条讲不清」，不能写「你不行」。状态是给证据的，不是给人的。

**已落地的原文**
- `这里不评价你，只判断证据够不够`（/projects）
- `系统会如实记下这件事，不会把它写成对你的评价。`（/projects/[id]/start）
- `我们不替你夸大，也不替你谦虚。状态只取决于证据本身`（/）

**反例（禁止）**：「你的基础比较薄弱」「这个项目做得不够好」「答得一般」

### 1.3 不替用户决定、不替他补写

系统可以建议、可以标出缺口，但不能偷偷改内容，也不能把缺失的判断补成完整的样子。

**已落地的原文**
- `不会替你决定。`（/resume/tailor 版本冲突）
- `差距分析会照着现在的样子算，不会替你补齐。`（/projects/[id]/report）
- `不会在你不知情时改写任何一句话`（/）
- `不会凭空判定为「已验证」`（/projects/[id]）
- `没有材料也不会被默认判定为「已验证」，答不上来的部分同样不会被补写。`（/projects/[id]/start）

## 2. 称呼与用词

| 项 | 规则 | 现有做法 |
|---|---|---|
| 人称 | **一律用「你」**，不用「您」 | 全站一致，无一处「您」 |
| 自称 | 用「系统」「证途」，或直接省略主语 | `系统会如实记下这件事` |
| 「候选人」 | **不出现在界面文案**，只在代码注释里用 | 界面零出现，注释里有（可接受） |
| 证据状态四词 | `已验证` / `用户声明` / `证据不足` / `当前缺失` —— **固定，不得改写** | 定义在 `packages/types` |
| 内容性质三词 | `事实` / `用户声明` / `建议` —— 固定 | 定义在 `packages/types` |

## 3. 慎用与禁用

### 3.1 禁用：任何效果承诺

`不承诺 Offer · 承诺每条结论有来源` 是登录 / 注册页逐字重复的承诺句，也是全站底线。

**禁用**：「帮你拿到 offer」「保证通过」「大幅提升面试通过率」「offer 收割机」

### 3.2 慎用：夸大与形容词

`不替你夸大` 是明写的。凡是加了形容词会让事实变重的说法，都要退回事实本身。

| 不要写 | 改写成 |
|---|---|
| 深度掌握 C 语言 | 用 C 语言写过 FreeRTOS 三任务模型 |
| 大幅提升系统性能 | 超调从 1.8℃ 降到 0.4℃ |
| 丰富的项目经验 | 两个项目共形成 10 条带来源的结论 |

### 3.3 禁用：无法兑现的「AI」表述 ⚠️

**当前有 3 处已失效，必须改**（AI 调用已从代码中摘除，改为本地规则实现）：

| 位置 | 现文案 | 问题 |
|---|---|---|
| `app/gap/page.tsx:82` | `去拷打模式，让 AI 挑你最薄弱的环节当场提问，答不上来当场给参考答案。` | 现在不是 AI 在挑 |
| `app/interrogate/page.tsx:16` | `AI 会照着你的项目经历和目标岗位，挑最薄弱的环节追问到底。` | 同上 |
| `app/resume/page.tsx:34` | `右边是 AI 改写后的推荐版本 ——` | 是规则改写，不是 AI 改写 |

**建议改法**：去掉主语里的「AI」，只说做了什么，例如 `照着你的项目经历和目标岗位，挑最薄弱的环节追问到底`。

**唯一保留「AI」的合法场景**：如实说明某功能需要 AI 但当前未接入 ——
`截图识别需要接入 AI 视觉能力，当前演示版尚未接入。请改用粘贴文本方式。`（`lib/job-gap-analysis.ts`）

### 3.4 慎用：戏剧化用词溢出

`拷打 / 审讯 / 供词 / 破绽` 是 **`/interrogate` 专属**的语域，不要外溢到其他页面。
它的反差本身就是设计的一部分：日常页面克制理性，只有拷打模式是审讯腔。

## 4. 两个语域

| | 克制区（大多数页面） | 强语气区（仅 /interrogate） |
|---|---|---|
| 用词 | 追问、深挖、证据、来源、缺口 | 拷打、审讯、供词、破绽、顶住 |
| 判断语 | `证据不足`、`还讲不透` | `没顶住`、`破绽不少`、`这块还得重做` |
| 边界 | 可以指出讲不清，不做人身评价 | 语气可以重，**仍然不做人身评价** |

强语气区的底线不变：`只有真正做过且讲得清楚的才算过关` —— 判的还是「讲没讲清」，不是「人怎么样」。

## 5. 已发现的不一致（待决）

以下都是真实存在的同义异说，会让人以为是不同东西。**给出建议但未擅自改**，请逐条确认。

| # | 问题 | 现状 | 建议 |
|---|---|---|---|
| 1 | **进度单位矛盾** | `/onboarding` 说 `四步开始`；工作台引导弹窗说 `用 5 步快速认识工作台` | 两者指的不是同一件事（前者是准备流程，后者是界面导览）。建议后者改写为 `用几步快速认识工作台` 或明确改成 `5 个界面导览点`，消除数字冲突 |
| 2 | 同一个「证据不足」多种说法 | `待补证据`（/dashboard）、`待补强`（/gap 摘要、/report 区块）、`与岗位有关，需补证据`（/gap 分组） | 保留状态四词的唯一写法；分组名可另起但要与状态词显式对应 |
| 3 | `用户声明` 一词两义 | 既是证据状态（`claimed`），又是内容性质（`claim`） | 两轴同名易混。可考虑内容性质改用 `你的陈述`，把 `用户声明` 留给状态 |
| 4 | 「深挖」与「追问」混用 | 按钮 `继续深挖`（/resume、/projects）vs `开始追问`（/start），指同一条流程 | 统一为一个词。「深挖」是模块名，「追问」是会话动作，建议按钮统一用 `开始追问` |
| 5 | 重做动作六种叫法 | `重新分析`/`重新解析`/`重新导入`/`换一份 JD`/`换一个岗位重新分析`/`重新开始一轮` | 按对象统一：同一对象用同一个动词 |
| 6 | 简历版本四种叫法 | `岗位专版`/`岗位专版简历`/`专版简历`/`保存为岗位专版` | 统一为 `岗位专版简历`（首次出现）→ `专版`（后续） |
| 7 | 演示态标注不一致 | /settings 三项都注明 `（本地演示，…）`；/projects/[id] 保存也注明；但 /resume/tailor 保存成功、/target/new 完成态未注明 | 凡「刷新即丢」的写操作，统一加 `（本地演示，刷新不保留）` |

## 6. 写新文案的自查

```
[ ] 这句话有没有承诺效果？（有 → 删）
[ ] 这句判断能不能指出依据？（不能 → 改成「证据不足」或补来源）
[ ] 有没有评价到「人」而不只是「证据」？
[ ] 有没有替用户做决定、或把缺失补成完整？
[ ] 用了「您」吗？（用了 → 改「你」）
[ ] 说了「AI」吗？（说了 → 确认是否属实；非「未接入」场景一律去掉）
[ ] 拷打/审讯类用词溢出到 /interrogate 之外了吗？
[ ] 证据状态四词、内容性质三词有没有被改写？
[ ] 是写操作提示吗？是 → 该加「（本地演示，刷新不保留）」吗？
```
