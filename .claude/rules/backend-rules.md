## 1. 适用范围

本规范用于 Web 后端/API 服务的架构、路由、Controller、Service、Repository、数据访问、认证授权、输入校验、错误处理、日志、缓存、任务、文件处理、第三方调用、配置、测试以及 AI Coding Agent 的代码生成和修改。

示例优先使用 Python + FastAPI 表达，但规则适用于其他后端框架。

规则类型：

- **【安全红线】**：绝不允许违反。
- **【强制规则】**：企业/项目级规范，必须执行。
- **【条件强制】**：满足场景时必须执行。
- **【建议】**：正常情况下应遵守。
- **【说明】**：规则解释。
- **【示例】**：正确/错误示例。
- **【例外】**：特殊情况必须显式记录。

---

## 2. 总体原则

```text
安全
  ↓
业务正确性
  ↓
数据一致性
  ↓
接口兼容性
  ↓
工程规范
  ↓
性能
  ↓
代码风格
```

企业强制规则不是建议。一个函数超过工程规定的最大行数，即使功能正确，也必须进行拆分或特殊审核。

---

## 3. 推荐架构

推荐采用：

```text
Router / Controller
        ↓
Service / Domain
        ↓
Repository / DAO
        ↓
Database
```

基础设施可单独管理：

```text
Cache
Message Queue
Object Storage
Third-party API
Authentication Provider
```

- 【强制规则】Controller/Router 负责协议层工作，不负责大段业务逻辑。
- 【强制规则】业务规则集中在 Service/Domain 层。
- 【强制规则】数据库访问集中于 Repository/DAO 或明确的数据访问层。
- 【强制规则】第三方 API 访问不得散落在业务代码中。

---

## 4. 后端项目结构

推荐：

```text
app/
├── api/
│   ├── routes/
│   └── dependencies/
├── schemas/       # 请求/响应模型
├── services/      # 业务逻辑
├── repositories/  # 数据访问
├── models/        # ORM/数据库模型
├── auth/          # 认证授权
├── core/          # 配置、日志、安全基础设施
├── tasks/         # 异步任务
├── utils/         # 通用工具
└── main.py
```

- 【强制规则】不得让 Router 直接进行复杂 SQL 和复杂业务计算。
- 【强制规则】不得让 Repository 决定用户是否有权限执行某个业务动作；授权边界通常应在 Service/API 层明确完成。

---

## 5. 文件和函数规模

默认企业规则：

- 【强制规则】单个后端源码文件原则上不超过 **400 行**。
- 【强制规则】单个函数原则上不超过 **80 行**。
- 【强制规则】单个 Service 方法原则上不超过 **120 行**。
- 【强制规则】特殊场景超过限制必须审核。
- 【强制规则】禁止删除空行、注释或压缩代码规避行数限制。
- 【强制规则】禁止无意义拆分。

---

## 6. API 设计

- 【强制规则】每个接口必须有明确 HTTP 方法、路径、请求模型、响应模型和错误语义。
- 【强制规则】列表接口必须分页或有明确上限。
- 【强制规则】不得默认返回无限数量数据。
- 【强制规则】状态码必须表达正确语义。
- 【强制规则】API 不得把内部数据库模型直接当作对外响应模型。
- 【强制规则】敏感字段必须显式排除。
- 【建议】使用统一错误响应格式。

---

## 7. API 授权：对象级权限

这是后端最重要的安全红线之一。

- 【安全红线】所有使用用户提供 ID 查询或修改资源的 API，都必须检查当前用户是否有权限操作该对象。
- 【安全红线】不能因为用户已经登录就默认拥有任何对象的访问权。
- 【强制规则】列表查询同样必须附带租户/用户/角色范围条件。

错误：

```python
@app.get('/orders/{order_id}')
def get_order(order_id: int):
    return db.get_order(order_id)
```

如果 `order_id` 属于其他用户，这就是对象级授权失效。

正确思路：

```python
order = repo.get_user_order(user_id=current_user.id, order_id=order_id)
if order is None:
    raise HTTPException(status_code=404)
```

OWASP API Security Top 10 将 Broken Object Level Authorization 列为 API 核心风险。citeturn340065search3

---

## 8. 功能级权限

- 【安全红线】普通用户不得访问管理接口。
- 【安全红线】不能因为前端隐藏“删除/管理”按钮就认为权限安全。
- 【强制规则】后端必须在服务端再次检查角色、权限或资源范围。
- 【条件强制】管理员、运营、审计等角色必须有明确权限矩阵。

---

## 9. 输入校验

- 【安全红线】所有外部输入都必须视为不可信。
- 【强制规则】请求体、Query、Path、Header、Cookie、上传文件、Webhook、第三方 API 数据都必须校验。
- 【强制规则】校验类型、长度、范围、枚举、格式和业务约束。
- 【安全红线】不得直接把用户输入拼接进 SQL、Shell、模板、表达式或文件路径。

---

## 10. SQL 注入

- 【安全红线】禁止使用字符串拼接生成 SQL。
- 【强制规则】必须使用 ORM 参数绑定或参数化 SQL。
- 【强制规则】动态排序字段、表名等不能直接接受任意用户输入，应使用 allow-list 映射。

错误：

```python
sql = f"SELECT * FROM users WHERE name = '{name}'"
```

正确：使用 ORM 参数绑定或：

```python
sql = "SELECT * FROM users WHERE name = :name"
params = {"name": name}
```

OWASP 将 SQL Injection 归于 Injection，并明确推荐参数化查询/Prepared Statements。citeturn644693search0turn644693search1

---

## 11. 认证

- 【安全红线】密码不得明文存储。
- 【安全红线】密码不得使用普通 SHA-256 等快速哈希直接存储。
- 【强制规则】优先使用 Argon2id；若因兼容性使用其他算法，必须采用经过验证的配置。
- 【强制规则】认证失败响应不能泄露“用户是否存在”等不必要信息。
- 【强制规则】登录、重置密码等流程必须进行速率限制。

OWASP 当前密码存储建议以 Argon2id 为首选，并要求每个密码使用唯一 salt。citeturn644693search4

---

## 12. Session / Cookie / Token

- 【强制规则】认证方案必须明确 Token/Session 生命周期。
- 【强制规则】Refresh Token、Session ID 等敏感凭据必须有撤销/失效机制。
- 【强制规则】使用 Cookie 认证时必须考虑 CSRF 防护。
- 【建议】浏览器场景优先采用安全 Cookie 或 BFF 设计。
- 【安全红线】不得在日志打印完整访问 Token、Refresh Token、Session ID。

OWASP 会话管理建议使用明确的 `Secure`、`HttpOnly`、`SameSite` 等 Cookie 属性；SameSite 应作为纵深防御，而不是在所有场景中单独代替 CSRF 防护。citeturn644693search6turn644693search2

---

## 13. CORS

- 【强制规则】生产环境显式列出允许 Origin。
- 【安全红线】不能无条件开放所有 Origin。
- 【条件强制】Cookie/credentials 场景不能将允许 Origin 配置为 `*`。
- 【强制规则】开发和生产配置分离。

FastAPI 文档明确指出，credentials 场景下不能让 `allow_origins`、`allow_methods`、`allow_headers` 都使用 `*`。citeturn684376search1

---

## 14. CSRF

- 【条件强制】Cookie/session 驱动的状态改变请求必须有 CSRF 防护。
- 【强制规则】所有状态改变操作使用 POST/PUT/PATCH/DELETE 等非安全方法，禁止使用 GET 修改资源。
- 【建议】结合 Origin/Referer 校验、SameSite 和 CSRF Token 形成纵深防御。

OWASP 建议有状态系统使用 synchronizer token 等 CSRF 防护，并明确指出 SameSite 通常应作为防御纵深。citeturn644693search2

---

## 15. SSRF

- 【安全红线】不得直接访问用户提供的任意 URL。
- 【条件强制】服务端主动请求外部资源时必须进行 URL allow-list、协议、端口、目标地址和重定向控制。
- 【强制规则】内部地址、云元数据地址等敏感网段必须根据部署环境进行阻断。

OWASP API Security Top 10 将 SSRF 列为重要 API 风险。citeturn340065search3

---

## 16. 文件上传

- 【安全红线】不能仅依赖文件扩展名判断类型。
- 【强制规则】限制大小、类型、数量和总上传容量。
- 【强制规则】上传文件不能直接使用用户文件名作为服务器真实路径。
- 【强制规则】文件保存位置与可执行目录隔离。
- 【建议】对高风险格式进行内容检查或转换。

---

## 17. 异常处理

- 【安全红线】不得把数据库异常、堆栈、SQL、内部路径直接返回给客户端。
- 【强制规则】统一异常处理层。
- 【强制规则】客户端只获得必要的错误信息和错误码。
- 【强制规则】服务端记录足够的排查上下文，但不得记录密码、Token 等敏感信息。
- 【强制规则】所有资源在异常路径必须正确释放。

---

## 18. 日志

日志至少需要区分：

```text
DEBUG
INFO
WARNING
ERROR
AUDIT
SECURITY
```

- 【强制规则】日志必须包含时间、模块、事件和必要上下文。
- 【安全红线】禁止记录密码、私钥、完整 Token、Session ID。
- 【强制规则】安全敏感事件必须可审计。
- 【建议】请求使用 trace_id/request_id 串联前后端和服务日志。

OWASP 2025 已将 Security Logging & Alerting Failures 单独列为 A09。citeturn340065search0turn340065search6

---

## 19. 限流与资源保护

- 【安全红线】认证、密码重置、短信/邮件发送等高风险接口必须有限流策略。
- 【条件强制】昂贵查询、导出、上传、AI 调用等资源密集接口必须限速或排队。
- 【强制规则】分页接口必须限制最大 page size。
- 【强制规则】不得允许用户通过一个请求触发无界数据处理。

OWASP API Security Top 10 包含 Unrestricted Resource Consumption。citeturn340065search8

---

## 20. 事务与一致性

- 【安全红线】多个必须同时成功或失败的数据库修改必须使用事务。
- 【强制规则】Service 层负责决定业务事务边界。
- 【强制规则】事务中不得执行不必要的长时间外部网络请求。
- 【条件强制】并发更新关键数据时必须明确锁、乐观锁或事务隔离策略。

PostgreSQL 默认隔离级别为 Read Committed；Serializable 提供更严格的隔离，但应用需要处理 serialization failure 和重试。citeturn913701search3turn913701search5

---

## 21. 缓存

- 【强制规则】缓存不能成为唯一事实来源，除非业务明确设计为缓存系统。
- 【强制规则】缓存 Key 必须包含必要的租户、用户或资源范围。
- 【强制规则】敏感数据缓存必须考虑 TTL 和失效策略。
- 【条件强制】写操作必须设计缓存一致性策略。

---

## 22. 第三方 API

- 【安全红线】不得默认信任第三方 API 返回的数据。
- 【强制规则】第三方响应同样必须校验。
- 【强制规则】必须处理超时、重试、熔断或失败降级。
- 【条件强制】重试只允许用于确定幂等或可安全重试的请求。
- 【强制规则】第三方 Secret 只能从安全配置中读取。

---

## 23. 幂等

- 【条件强制】支付、创建订单、资源扣减、任务提交等可能重复触发的操作必须设计幂等机制。
- 【建议】通过业务唯一键或 idempotency key 实现。

---

## 24. API 版本

- 【强制规则】公共接口发布后不得随意破坏兼容性。
- 【强制规则】破坏性变更应通过版本化或兼容迁移完成。
- 【强制规则】不得直接修改客户端依赖的字段语义。

---

## 25. 配置管理

- 【安全红线】密码、Secret、私钥不得写入 Git。
- 【强制规则】开发、测试、生产配置分离。
- 【强制规则】生产环境必须通过部署平台/Secret 管理系统提供敏感配置。
- 【强制规则】配置启动时进行类型和必填项校验。

---

## 26. 后端测试

至少覆盖：

```text
正常业务
参数错误
未登录
权限不足
对象不存在
重复请求
并发请求
数据库失败
第三方超时
外部恶意输入
```

- 【强制规则】安全关键接口必须有权限测试。
- 【条件强制】核心写操作必须有事务/并发测试。

---

## 27. AI Coding Agent 规则

### 修改前

- 【强制规则】先理解模块、API、Service、Repository 和数据流。
- 【强制规则】先确认认证授权方式。
- 【强制规则】先确认数据库事务边界。
- 【强制规则】不得先写代码再猜接口行为。

### 修改中

- 【强制规则】最小修改。
- 【强制规则】禁止无关重构。
- 【安全红线】不得删除鉴权检查。
- 【安全红线】不得删除输入校验。
- 【安全红线】不得直接拼接 SQL。
- 【安全红线】不得为了“方便”把敏感数据写进日志。
- 【强制规则】不得绕过 Service 层直接从 Router 修改数据库，除非项目架构明确允许。

### 修改后

```text
[ ] 认证正确
[ ] 对象级权限正确
[ ] 功能级权限正确
[ ] 输入已校验
[ ] SQL 参数化
```
