## Purpose

让用户的简历更匹配目标岗位，同时降低过度包装导致的面试风险——每一条强化表述都必须能追溯到一条已有来源的证据。

## ADDED Requirements

### Requirement: 证据门禁

系统提出的简历修改建议 MUST 只使用已验证或经用户确认的事实。

未经验证的技术、量化指标、项目成果与职责 MUST NOT 被自动写入简历建议。

每一条建议 MUST 可展开查看其证据来源。

当某条建议没有可追溯的来源时，该条 MUST 在界面上不可被接受，且 MUST 说明原因。

#### Scenario: 未验证内容不出现在建议中

- **WHEN** 某技术的能力状态为「用户声明」或「证据不足」
- **THEN** 系统不提出把该技术强化写入简历的建议

#### Scenario: 无来源的建议不可接受

- **WHEN** 某条建议不存在可追溯的证据来源
- **THEN** 用户无法接受该条建议，并看到不可操作的原因说明

#### Scenario: 展开建议来源

- **WHEN** 用户查看某条建议的来源
- **THEN** 系统展示该建议所依据的证据记录或已确认事实

### Requirement: 逐条审核

用户 MUST 能对每条建议分别执行接受、编辑或拒绝，且每条的处理状态 MUST 被保存。

保存岗位专版简历时，若仍有未处理的建议，系统 MUST 提示剩余条数，并要求用户确认。

#### Scenario: 接受一条建议

- **WHEN** 用户接受某条建议
- **THEN** 该建议的内容反映到简历预览中，该条状态更新为已接受

#### Scenario: 编辑一条建议

- **WHEN** 用户修改某条建议的内容后确认
- **THEN** 简历预览反映用户编辑后的内容，而非系统原始建议

#### Scenario: 拒绝一条建议

- **WHEN** 用户拒绝某条建议
- **THEN** 该条不进入简历，状态更新为已拒绝

#### Scenario: 保存时仍有未处理建议

- **WHEN** 用户在存在未处理建议时执行保存
- **THEN** 系统提示剩余条数并要求确认

### Requirement: 岗位专版简历与版本绑定

保存后的简历版本 MUST 与当前主目标岗位绑定，并 MUST 展示版本号、生成时间与绑定的岗位名。

系统 MUST NOT 生成可泛投所有岗位的通用版本；同一岗位已存在版本时，系统 MUST 要求用户明确选择新建版本或覆盖。

#### Scenario: 保存后绑定岗位

- **WHEN** 用户保存岗位专版简历
- **THEN** 该版本记录其绑定的主目标岗位、版本号与生成时间

#### Scenario: 同岗位已有版本

- **WHEN** 用户为已存在简历版本的主目标岗位再次保存
- **THEN** 系统提示新建版本或覆盖，用户明确选择后执行

#### Scenario: 无可建议内容

- **WHEN** 当前证据不足以支撑提出任何修改建议
- **THEN** 系统不生成建议，并提示先补齐项目验证
