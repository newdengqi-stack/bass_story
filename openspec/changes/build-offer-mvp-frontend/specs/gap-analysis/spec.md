## Purpose

把目标岗位的要求与用户的证据逐项对上，让用户知道自己离岗位差什么，以及在有限时间里应当先补哪一项。

## ADDED Requirements

### Requirement: 四类能力分类

系统 SHALL 把岗位要求逐项分类为四种结果之一：已具备且可强调、与岗位有关但需补证据、当前缺失且必须处理、硬性条件。

硬性条件（学历、专业、年限等）MUST 单独分区展示，MUST NOT 与可通过项目补强的能力混排，且该分区 MUST 明确说明这些条件无法用项目弥补。

每一项能力 MUST 展示岗位相关性、证据状态、准备成本与时间紧迫度。

#### Scenario: 硬性条件独立展示

- **WHEN** 用户查看差距分类结果
- **THEN** 学历、专业、年限等条件出现在独立分区，且带有"不可用项目弥补"的说明

#### Scenario: 查看单项能力的依据

- **WHEN** 用户查看某一项能力
- **THEN** 系统展示该项的岗位相关性、证据状态、准备成本与时间紧迫度

### Requirement: 排序依据可解释

差距结果的排序 MUST 可展开查看其依据，依据 MUST 包含岗位相关性、时间紧迫度与证据状态三项，MUST NOT 呈现为无法解释的黑盒评分。

当所有相关能力的证据均不足时，系统 MUST NOT 生成结论性判断，而 MUST 提示用户先补齐项目验证。

#### Scenario: 展开排序依据

- **WHEN** 用户要求查看某项能力的排序理由
- **THEN** 系统展示岗位相关性、时间紧迫度与证据状态三项依据

#### Scenario: 证据全部不足

- **WHEN** 与岗位要求相关的证据全部处于不足或缺失状态
- **THEN** 系统提示先补齐项目验证，而不是给出虚假的差距结论

### Requirement: 冲刺任务与固定时长档位

系统 SHALL 为差距生成下一步冲刺任务。每个任务的预计时长 MUST 取自固定档位：15、30、45、60、90 分钟，MUST NOT 生成档位之外的时长。

每个任务 MUST 包含：任务标题、任务目标、完成定义、再次验证方式，以及所关联的能力标签。

当某项工作的规模超过 90 分钟时，系统 MUST 将其拆分为多条任务，MUST NOT 生成超过档位上限的任务。

#### Scenario: 任务时长取固定档位

- **WHEN** 系统生成任意一条冲刺任务
- **THEN** 该任务的预计时长是 15、30、45、60 或 90 分钟之一

#### Scenario: 超出上限时拆分

- **WHEN** 某项待补工作的规模超过 90 分钟
- **THEN** 系统将其拆分为多条不超过 90 分钟的任务

#### Scenario: 任务包含完成定义

- **WHEN** 用户查看任意一条冲刺任务
- **THEN** 该任务显示完成定义与再次验证方式，而不只是标题

### Requirement: 任务状态变更反馈到差距

用户完成任务或跳过任务后，系统 MUST 就地更新对应的能力状态，并 MUST 让用户看到状态发生的变化。

#### Scenario: 完成任务后状态更新

- **WHEN** 用户将某条任务标记为完成
- **THEN** 与该任务关联的能力状态就地更新，并提示用户变化结果

#### Scenario: 跳过任务

- **WHEN** 用户跳过某条任务
- **THEN** 该任务被标记为跳过，且不影响其他任务的状态

#### Scenario: 没有可生成的任务

- **WHEN** 当前证据无法支撑生成任何任务
- **THEN** 系统给出补充项目证据的出口
